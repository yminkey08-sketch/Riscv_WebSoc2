## Verilator 仿真 TCP/HTTP 端到端全通，固件完整功能验证

### 关键结论（先说结果）
- ✅ TCP 握手：SYN → SYN+ACK → ACK → ESTABLISHED（端口/seq/ack/flags 全对）
- ✅ HTTP GET（根路径）→ 200 OK + HTML 页面（flags=ACK|FIN）
- ✅ 第二条 TCP 连接（源端口 12346）→ `GET /led/0F` → LED=0x0F
- ✅ ARP、ICMP、TCP（单/多连接）、HTTP 全链路验证通过

### 核心问题与解决

**问题 1：TCP SYN+ACK 畸形（端口/seq/ack=0、flags=0x50）**
- 现象：固件回复的 SYN+ACK 各字段全 0，TCP 握手无法继续
- 根因：`xpm_memory_tdpram_sim.v` 写逻辑 `mem[addrb] <= dinb` 忽略了字节使能（web），把 `sb`/`sh` 字节写入错当成整字写入，破坏了指令 RAM 里相邻的 `connection_*` 数组（全变 0）
- 解决：wea/web 端口宽度改为 `WRITE_DATA_WIDTH/BYTE_WRITE_WIDTH`，写逻辑改成 per-byte（按 group 分组）：`for(_g_) if(wea[_g_]) for(_b_) mem[addr][(_g_*_GPA_+_b_)*8+:8] <= din[...]`，兼容 BYTE_WRITE_WIDTH 8/16/32

**问题 2：需要状态化 testbench**
- 固件 SYN+ACK 的 seq 是 `LCPU_LOCAL_TIME_L()`（硬件 rdcycle 计数器），无法硬编码
- 解决：testbench 解析 TX 捕获的 SYN+ACK（dst_port、fpga_seq），动态构造 ACK（ack=fpga_seq+1）和 HTTP GET；用 dst_port 区分两条连接（12345/12346）
