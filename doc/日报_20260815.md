# 日报 2026-08-15

## 重新学习固件 — 第1天：寄存器头文件 + eth 层

> 从头逐层理解 TCP/IP + HTTP 固件，今天只吃透最底下的两层：寄存器头文件和以太网层。

### 学到了什么

**寄存器头文件（`c/inc/lcpu_general.h`）**：整个固件跟硬件打交道的入口。它把以太网 MAC 的两块内存映射寄存器区——RX FIFO（读侧 `0x80006000`）和 TX FIFO（写侧 `0x80006100`）——封装成一组 C 宏。固件里收包就是「查空标志 → 设读地址 → 读一字节」，发包就是「设写地址 → 设数据 → 打写使能」，全程不用背那些 `0x80000000` 开头的裸地址——相当于给硬件做了个"遥控器"。

更妙的是它用的是**「原地 FIFO」模型**：包在 MAC 的一块共享缓冲区里躺着，CPU 不是把整包拷到内存里再处理，而是用「地址指针 + 逐字节读写」直接对着缓冲区操作；回包也直接在同一个缓冲区里原地改写（换掉 MAC 地址、IP、校验和），最后 push 出去。省掉了整帧 `memcpy`。

具体寄存器分工（`lcpu_general.h:17-34`）：

| 方向 | 寄存器 | 作用 |
|------|--------|------|
| RX 读侧 | `_RD(0)` | 空标志（非 0 = 没有新包） |
| | `_RD(2)` | 当前包长度 |
| | `_RD(5)` | 读地址指针（设了它，`_RD(6)` 就返回该地址的字节） |
| | `_RD(6)` | 读出的 1 字节数据 |
| TX 写侧 | `_WR(2)` | 写地址 |
| | `_WR(3)` | 写数据 |
| | `_WR(1)` | 写使能脉冲（真正写入的那一下） |
| | `_WR(4)+_WR(6)` | 提交整包，触发发送 |

**eth 层（`c/eth.c`）**：干两件事——① 读以太网帧的「类型字段」（字节 12-13），看是 `0x0800`(IP) 还是 `0x0806`(ARP)，决定这个包丢给谁；② 判断是发给本机的包后，**顺手把回包的 MAC 头先写进 TX FIFO**（写本机 MAC 当源地址、把对方的 MAC 拷过来当目的地址），这样上层 ip/arp 构造回包时就不用再管 MAC 头了——"边收边发，省一步"。

### 关键精髓

- **偏移量就是协议栈的"地图"**：`OFF_ETH_TYPE=12`、`OFF_IP_SRC_IP=26`、`OFF_TCP_SEQ_NUM=38`…… 每个字段在帧里的位置都用宏定义好了，解析就是"按图索骥"，代码里几乎看不到魔数。
- **分层思想**：eth 只认"以太类型"这一件事，具体是 IP 还是 ARP 它不关心，丢给上层。每层职责单一，改哪层不影响别的层。
- **收/发用两套独立寄存器**：RX 有读指针、TX 有写指针，互不干扰——这是「原地 FIFO」能同时边收边回包的基础。
