## 重新梳理 TCP/IP + HTTP 固件架构

### 主题
系统性地重读并整理了 `c/` 目录下整套裸机固件（共 1192 行），把协议栈从硬件接口到 HTTP 应用层串成完整认知。今天为纯学习/复习，无代码修改。

### 梳理的架构要点

**1. 硬件寄存器接口（`inc/lcpu_general.h`）—— 原地 FIFO 模型**
- CPU 不直接操作帧内存，而是通过「地址寄存器 + 数据寄存器」逐字节读写共享包缓冲
- RX 读侧 `_RD(n)`（0x80006000 基址）：`_RD(0)`空标志 / `_RD(2)`包长 / `_RD(5)`读指针 / `_RD(6)`数据
- TX 写侧 `_WR(n)`（0x80006100 基址）：设地址→设数据→`_WR(1)`写使能，最后 `_WR(4)+_WR(6)` 提交整包

**2. 主循环分发（`main.c`）**
- `tcp_periodic_check()`（每轮必调）→ 轮询 `LCPU_RD_EMPTY()` → 弹包 → `eth_proc()` 按以太网类型分流 → `ip_proc()` 按 IP 协议号再分流 → ARP/ICMP/TCP 处理 → `_RD(1)=1` 释放

**3. 各协议层**
- `eth.c`：读 ethertype，IP 包预先交换 MAC
- `arp.c`：校验 target IP + opcode，构造 reply（sender/target 交换）
- `ip.c`：校验 version/IHL/目的 IP，`ip_header_update()` 原地改写 IP 头（总长/地址交换/校验和）
- `icmp.c`：type 改 0 + 回显 payload + 重算校验和

**4. TCP 状态机（`tcp.c`）—— 核心**
- 并行数组连接表（8 slot），四元组 (src_ip, src_port, dst_ip, dst_port) 唯一标识
- 服务器侧被动打开状态机：CLOSED → SYN_RECEIVED → ESTABLISHED → FIN_WAIT_1/2 → TIME_WAIT / LAST_ACK
- 初始 seq 用 `rdcycle` 硬件计数器（`connection_seq_nums = LCPU_LOCAL_TIME_L()`）
- `tcp_periodic_check()` 处理三种超时：TIME_WAIT 回收、空闲 RST、SYN 重传（最多 3 次）

**5. HTTP 处理（`tcp.c:290-335`）**
- 解析 `"GET "`，识别 `/led/XX` 路径 → 十六进制转 LED 值 → 写硬件寄存器 `LCPU_BASE + 0x10*4`
- `send_http_response()` 按 MSS=1024 分块，末段 piggyback FIN，省一次来回

**6. 校验和**
- 反码求和：`cks_sum_cal()` 折叠进位（`while(sum>>16) sum=(sum&0xFFFF)+(sum>>16)`）
- IP 校验和（仅头 20 字节）、TCP 校验和（伪首部+头+数据）、ICMP 校验和（type 改后重算）
