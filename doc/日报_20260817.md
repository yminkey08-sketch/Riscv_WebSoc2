# 日报 2026-08-17

## 重新学习固件 — 第3天：ip 层

> 按计划吃透 ip 层：IP 是「跨网络寻址」的信封，今天理解 `ip.c` 怎么校验收包、怎么原地改写回包 IP 头、校验和怎么算。

### 学到了什么

**ip 层（`c/ip.c`，117 行）**：一收一发两个函数——收包时 `ip_proc()` 做「校验 + 提取信息」，发包时 `ip_header_update()` 做「原地改写 IP 头」。IP 头在以太网头之后 14~33 字节（20 字节）。

**`ip_proc()` 四步校验（收包）**：

1. version==4 且 IHL>=5（字节 14，高 4 位/低 4 位；IHL 单位 4 字节，5→20 字节标准头）
2. 目的 IP == 本机（字节 30-33 逐字节比对 `Local_IP_ADDR`）
3. 读源 IP 存全局 `src_ip`（大端拼接，回包时当目的地址用）
4. 读 protocol（1=ICMP/6=TCP/17=UDP）决定分发 + 读 total_len 给上层算 payload

**`ip_header_update()` 五类分支（回包原地改写，遍历 20 字节）**：

| 字节 | 写什么 | 原因 |
|------|--------|------|
| total_len (16-17) | 新总长 | 回包长度变了 |
| src IP (26-29) | 本机 IP | 源/目的交换 |
| dst IP (30-33) | 对方 IP(src_ip) | 源/目的交换 |
| checksum (24-25) | 新校验和 | 头内容变了 |
| 其余所有字节 | 从 RX 原样拷回 | version/TTL/protocol 不能瞎编 |

**IP 校验和（1's complement 反码求和）**：只对 20 字节头、checksum 字段置 0、每 2 字节拼 16 位累加、溢出折叠进位、最后取反。核心折叠在 `comlib.c` 的 `cks_sum_cal()`。用真实头演算一遍：`0x4500+0x003C+0x4001+0xA9FE+0x23BA+0xA9FE+0x0101` 累加 = `0xFDF5`，取反 = `0x020A`。验证：接收方把含校验和的整个头再求和应得 `0xFFFF`。

### 关键精髓

- **大端字节序**：线上第一个字节是最高的，拼接用 `<<24/<<16/<<8/<<0`，拆解用对应右移。
- **源/目的交换**：回包本质就是把「本机 IP 变 src、对方 IP 变 dst」，其余字段不动。
- **能照抄的别自己编**：IP 头除 4 个必改字段外全部原样保留——之前有人硬编码 protocol 导致 ICMP 包被当成别的协议，ping 直接挂。
- **回包分工流水线**：eth 写 MAC 头（第1天）→ ip 改 IP 头（今天）→ 上层写负载（后几天），各管各的。这也是「TCP 发包不能脱离收包流程」的根因。
