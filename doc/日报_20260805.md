## 任务一：Ping 固件源码修复与验证

### 进展和结果
- 将 `RiscV_webSoC2(2).7z` 中能 ping 通的源码同步到工作目录，确认基线可用
- 修复 `linker.ld`：加 `/DISCARD/ : { *(.note*) *(.comment*) }` 解决 GCC 12.2.0 的 `.note.gnu.build-id` 占据地址 0 的问题
- 确认 `updatemem` 必须使用 v3 项目的 `RiscV_WebSoC_v3base.bit` 作为 base bitstream（`impl_1/webserver_cpu_top.bit` 不可用）
- Ping 169.254.1.1 验证通过，5/5 包 0% 丢包，延迟 ~0.8ms

### 遇到的问题
1. **updatemem 后固件不运行**：多次烧录后 ping 不通的原因是 bank 文件过期——`c_build` 生成 bank 后没正确拷贝到 `build_xilinx`，updatemem 用的是旧 bank 文件
2. **PHY 建链延迟**：FPGA 重新烧录后 PHY 需要约 5 秒重新建立链路，刚烧完立即 ping 会 "Destination Host Unreachable"

### 解决方法/经验总结
- 编译→生成 bank→拷贝 bank→updatemem→烧录 必须在正确的目录执行，updatemem 必须从 `build_xilinx/` 运行
- 烧录后等 5 秒再 ping，用 5 个包而不是 1 个（第一个包触发 ARP 学习）

## 任务二：TCP 协议栈代码实现

### 进展和结果
- 完成 TCP 三步并行开发：
  - **步骤 1 发送发动机**：`fill_tcp_header()` + `tcp_checksum()` + `send_tcp_seg()` → TX FIFO 写 TCP 段 + 校验和
  - **步骤 2 接收解析器**：`tcp_packet_handler()` 从 RX FIFO 读 IP 头 + TCP 头，解析 flags/seq/ack/port
  - **步骤 3 连接表管理**：并行数组 `connection_states[]`/`connection_seq_nums[]`等，MAX_CONNECTIONS=4
- 完整 TCP 状态机：CLOSED → SYN_RECEIVED → ESTABLISHED → FIN_WAIT → TIME_WAIT → LAST_ACK
- 定时器：`tcp_periodic_check()` 处理 TIME_WAIT 超时、空闲超时 RST、SYN+ACK 重传
- 编译通过，固件 4.9KB，Ping 仍正常

### 遇到的问题
- **TCP 三次握手未通过**：`nc -vz 169.254.1.1 80` 超时，FPGA 未回 SYN+ACK
- 已添加 LED 调试断点：eth_proc 检测 IP 包→LED=0x04，ip_proc 检测 TCP→LED=0x02，tcp_packet_handler 进入→LED=0x01。待观察 LED 定位卡在哪一步
- 反汇编验证了 `send_syn_ack()` 的 TX 写序列（WADDR→WDATA→WEN→PUSH），寄存器地址和写入顺序均正确

### 解决方法/经验总结
- 上板硬调 TCP 效率太低（改代码→编译→updatemem→烧录→等待→测试，每次 2+ 分钟）
- 决定搭建 iverilog 仿真环境，直接在仿真中看 GMII 总线上的收发包
