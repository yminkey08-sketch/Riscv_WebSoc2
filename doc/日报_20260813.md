# 日报 2026-08-13

## 修复 Verilator 以太网 RX 1字节移位，ARP/ICMP 端到端打通

### 关键结论（先说结果）
- ✅ ARP 请求→回复：dst/src MAC、IP、oper=2 全对，FCS 正确
- ✅ ICMP echo→reply：type=0、IP 交换、payload 回显、IP 校验和=0xFFFF
- ✅ 包长度 rpkt_len=42 正确
- ⏳ TCP 握手、HTTP 待验证

### 核心问题与解决

**问题 1：RX 数据整体左移 1 字节（0x00 被丢弃）**
- 现象：eth_presemble 输入 `in=11`（应为 00），后续字节全部错位
- 根因：`sim_main.cpp` 的 GMII RX 时钟公式 `(((t+2000)/4000)%2)` 使上升沿落在 `t=2000+8000k`，但数据字节中点在 `t=8000k`；上升沿时刻大多不是仿真 eval 循环的访问时刻（2500/4000/10000 倍数），posedge 被推迟，`0x00` 字节采样点被跳过
- 解决：时钟改为 `((t/4000)%2==0)`，上升沿落在 `t=8000k`（字节中点，全是 4000 倍数，循环必访问）

**问题 2：RDATA 返回"地址值"（误判，非 bug）**
- 现象：`dbg_bus_rdata` 显示上一个 RADDR 的地址值
- 根因：`rdata` 是寄存器输出，`reg_ack→rdata` 有 2 拍延迟，调试打印在 bus_req 上升沿取值读到了旧值
- 结论：是调试打印时机问题，不是硬件 bug。实际 `cpu_rd_rdata` 完全正确（raddr=12→08、13→06、0→ff）

**问题 3：SIM_END 整数溢出**
- 现象：加 ICMP 测试后仿真提前退出（loop 在 5690ns 就结束）
- 根因：`200000*20000 = 4×10⁹ > INT_MAX`，int 溢出成负数
- 解决：改用 `1000000ULL*1000`
