# 日报 2026-08-12

## Verilator 以太网调试

### 今天解决了什么
用 fpga_ila 软逻辑分析仪抓到内部信号，定位了以太网 RX 路径断点，修好了一个关键 bug。

### 问题 1：数据包无法到达 CPU（已解决）

**现象**：GMII 接口收到了 ARP 包，但 CPU 的 RX FIFO 永远为空。

**根因**：`dual_clock_fifo` 的 `read_data` 是组合逻辑输出。FIFO 读空后 `out_ptr` 不再递增，`read_data` 保持最后一个值（含 `dv=1`）→ `eth_presemble` 的 `rx_valid_header` 永远不复位 → `mac_rx_en` 卡死 → 后续数据包全部失效。

**修复**：`gmii2mac.v` 一行改动，用 `!rx_afifo_empty` 门控 dv 信号：
```verilog
.rx_data_en_in(rx_afifo_data[8] && !rx_afifo_empty),
```

**验证**（soft_ila 抓取）：`presemble_valid` 从 1024(卡死) → 16(正常)，CPU 能收到包。

### 问题 2：CPU 收到包但不回复（待解决）

**现象**：CPU 的 RX FIFO 有数据（`cpu_rd_empty=0`），但 `bus_req` 始终为 0，CPU 不做任何总线访问，`gmii_tx_en` 从未拉高。

**排查**：
- `--x-assign 0` 排除 X 传播 → 无效
- 已给 `riscv32_localbus`/`riscv32_top` 加 `cpu_trap`/`cpu_valid`/`cpu_addr` 调试端口
- 下一步 dump PicoRV32 内部状态（PC/trap）定位卡点
