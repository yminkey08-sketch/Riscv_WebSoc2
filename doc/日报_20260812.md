### 进展和结果

- 使用 soft_ila 精确定位以太网 RX 路径断点：**async FIFO 读空后 read_data 保持最后值（dv=1）导致 eth_presemble 锁死**

- 验证修复效果：`presemble_valid` 从 1024(卡死) → 16(正常)，`cpu_rd_empty` 可以拉低
- 确认 CPU 能收到数据包，但不回复
- 添加 PicoRV32 trap/valid/addr 调试端口（riscv32_localbus → riscv32_top → lcpu_riscv_wrapper）

### 遇到的问题
1. **dual_clock_fifo 读空后 data 保持**：`read_data = mem_array[read_addr]` 是组合逻辑，FIFO 读空后 `out_ptr` 不复进，`read_data` 保持最后值 → dv=1 锁死 eth_presemble
2. **Verilator `%m` 字节反转**：需同时解析正序和逆序括号
3. **`reg [127:0]` = 16字节不是128字节**：文件名截断
4. **`// Verilator` 注释被当作 pragma**：报 "Unknown verilator comment"
5. **riscv32_top 老式端口声明**：需在端口名列表和方向声明两处添加新端口

### 当前状态
- ✅ RX 路径修复：GMII → async FIFO → eth_presemble → mac_rx → cpu_channel
- ❌ TX 路径：CPU 收到包但不回复
  - `bus_req` 始终为 0（CPU 无总线访问）
  - `gmii_tx_en` 始终为 0（无 TX 输出）
  - CPU 可能处于 trap/异常状态
  - `--x-assign 0` 已排除 X 传播
  - `cpu_rd_empty=0` 和 `afifo_empty=0` 持续卡死，说明 FIFO 中有残留数据
