### 学到了什么

**TCP 和前几层本质区别**：IP/ICMP 无连接、无状态、包是独立的；TCP 有连接（先握手）、可靠（序号+确认）、数据是字节流（seq 是字节编号）、有状态机。所以 TCP 是这套固件里唯一「有记忆」的协议。

**TCP 头（20 字节，偏移 34 起）**：源/目的端口(0-3)、序号(4-7)、确认号(8-11)、data offset(12)、**flags(13)**、窗口(14-15)、校验和(16-17)。flags 每个 bit 一个含义：`FIN=0x01 SYN=0x02 RST=0x04 PSH=0x08 ACK=0x10 URG=0x20`，`SYN|ACK=0x12`。

**连接表（并行数组，`tcp.c:7-18`）**：最多 8 条连接，不用结构体，用「并行数组」——同一下标在多个数组各取一个字段（state/seq/ack/src_port/dst_port/src_ip/dst_ip）。一条连接用四元组 `(src_ip, src_port, dst_ip, dst_port)` 唯一标识，`find_connection()` 遍历匹配。

**三次握手（seq/ack 演算，PC_ISN=0x1000）**：

```
① PC→FPGA  [SYN]      seq=0x1000,  ack=无,    flags=SYN
② FPGA→PC  [SYN+ACK]  seq=FPGA_ISN, ack=0x1001, flags=SYN|ACK
③ PC→FPGA  [ACK]      seq=0x1001,  ack=FPGA_ISN+1
```

关键点：
- **FPGA 初始序号用 `rdcycle`**（`connection_seq_nums = LCPU_LOCAL_TIME_L()`），运行期才知道——所以之前仿真 testbench 必须从 SYN+ACK 里解析出 FPGA seq
- `tcp_handle_syn()` 收到 SYN：找空闲 slot，记四元组，`ack_nums = sn+1`，回 SYN+ACK
- `fill_tcp_header()` 回包时**端口交换**：SRC=本机(80)、DST=对方(12345)
- 第三步校验 `an == seq+1` 才进 ESTABLISHED，然后 `seq++`——因为 **SYN 也消耗一个序号**

**状态机（`tcp.h:8-15`，8 状态）**：今天前 3 个——CLOSED → SYN_RECEIVED → ESTABLISHED。这是服务器侧被动打开路径，没有 SYN_SENT（FPGA 从不主动连别人）。

**TCP 校验和（伪首部）**：和 IP/ICMP 最大的不同是多了**伪首部**——源IP(4)+目的IP(4)+保留(1)+协议号(1=6)+TCP长度(2)，再加 TCP 头和 payload。伪首部不传输，只在计算时临时拼，目的是让校验和绑定 IP 地址，防 NAT 改地址后 TCP 段还「看起来正确」。

### 关键精髓

- **三种校验和对比**（第3/4/5天各一种）：IP 算 20 字节头；ICMP 算整包；TCP 算伪首部+头+数据。底层都是同一个 `cks_sum_cal()` 反码折叠。
- **SYN/FIN 占序号**：即使不带数据也消耗一个序号，所以握手第三步 ack=ISN+1、seq++。
- **并行数组 vs 结构体数组**：资源受限裸机环境下并行数组访问更规整、编译器生成代码更紧凑。
- **分工流水线收口**：TCP 写 `send_tcp_seg()` 从偏移 34（eth+ip 头之后）开始写，MAC/IP 头一概不碰。
