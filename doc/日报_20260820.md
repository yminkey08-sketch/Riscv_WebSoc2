# 日报 2026-08-20

## 重新学习固件 — 第6天：tcp 层（四次挥手 + 超时维护）

> 昨天讲「建连接」（三次握手），今天讲「拆连接」（四次挥手）和 `tcp_periodic_check()` 超时维护，合起来是完整的 TCP 生命周期。

### 学到了什么

**为什么是四次挥手**：TCP 全双工，两个方向必须各自独立关一次（每个方向一次 FIN + 一次 ACK）。建连接三次就够了，因为 SYN 能捎带 ACK。

**被动关闭（PC 先发 FIN，`tcp.c:281-289`）**：ESTABLISHED 收到 FIN 后，ACK 和自己的 FIN 一起发，直接进 LAST_ACK：

```
① PC→FPGA  [FIN]      seq=X
② FPGA→PC  [ACK]      ack=X+1      ← 确认 PC 的 FIN
③ FPGA→PC  [FIN+ACK]  seq=Y, ack=X+1  ← 自己的 FIN（seq++ → Y+1）
④ PC→FPGA  [ACK]      ack=Y+1      ← LAST_ACK 收到它才 close_connection
```

- 简化点：跳过了标准 TCP 的 CLOSE_WAIT 状态（FPGA 的「应用」就是协议栈本身，没别的事要等）

**主动关闭（FPGA 先发 FIN，如 HTTP 发完就关，`tcp.c:340-356`）**：FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED：

- FIN_WAIT_1：等 ACK（→FIN_WAIT_2）或直接收到对方 FIN（同时关闭 →TIME_WAIT）
- FIN_WAIT_2：自己的 FIN 已确认，只等对方 FIN
- TIME_WAIT：双方都关了，但还要等 2MSL 再回 CLOSED

**TIME_WAIT 等 2MSL 的原因**：① 兜底最后一个 ACK——若 ④ 丢了对方会重传 FIN，还能再回一次 ACK；② 让旧包「死透」——四元组过 2 个 MSL 才能复用，防旧包串进新连接。

**RST 处理（`tcp.c:262`）**：收到 RST 直接 `close_connection()`，不回任何包。用于异常终止（端口没监听、状态错乱、超时强踢）。

**超时维护 `tcp_periodic_check()`（`tcp.c:361-380`）**：主循环每轮必调，管三件事（都用 `rdcycle` 计时）：

| 超时 | 常量 | 值 | 约等于 |
|------|------|-----|--------|
| TIME_WAIT 回收 | `TCP_TIMEWAIT_TICKS` | 100M | 2s |
| 空闲踢连接 | `TCP_IDLE_TIMEOUT_TICKS` | 2000M | 40s |
| SYN 重传间隔 | `TCP_SYN_RETRY_TICKS` | 150M | 3s |

- TIME_WAIT 等够 2s → close
- 非 TIME_WAIT 太久没活动 → 发 RST 强踢
- SYN_RECEIVED 的 SYN+ACK 没等到 ACK → 重发（最多 `TCP_SYN_MAX_RETRIES`=3 次）

### 关键精髓

- **两个时间戳分开记**：`connection_last_activity`（任何收包刷新，表示「还活着」）和 `connection_last_tx_time`（只有发包刷新，专给 SYN 重传计时）。分开才能避免对方发垃圾包导致 SYN+ACK 永远不重传。
- **无符号减法天然抗溢出**：`rdcycle` 32 位会回绕，但 `now - last` 用无符号减法，回绕后差值仍正确——嵌入式超时判断的经典技巧。
- **SYN/FIN 都占序号**：被动关闭里发完 FIN 要 `seq++`，LAST_ACK 校验 `an == seq` 才关。
- **漏调 `tcp_periodic_check()` 的后果**：LAST_ACK/TIME_WAIT 永远不回收，8 个 slot 占满，新连接进不来。所以主循环第一行就是它。
